# execenv

`execenv` — небольшая Unix-oriented entrypoint-утилита для контейнеров.
Она подставляет значения переменных окружения в плейсхолдеры `${VAR}` в одном или нескольких файлах, а затем может заменить свой процесс другим процессом через `exec(2)`.
Это полезно, когда приложению нужен статический конфигурационный файл, но итоговые значения известны только в момент запуска контейнера.


## Мотивация

`execenv` в первую очередь рассчитан на контейнерные образы, в которых конфигурацию нужно передавать во время запуска, а не во время сборки.
Типичный пример — frontend или приложение на основе distroless-образа. Один и тот же образ может использоваться в нескольких окружениях: development, staging и production. Вместо пересборки образа под каждое окружение можно хранить шаблон конфигурации внутри образа и рендерить итоговый файл при старте контейнера.
Утилита решает проблему минималистичных контейнеров, в которых нет оболочки (shell) и стандартных Unix-утилит. В таких контейнерах нельзя использовать привычный конвейер вида `envsubst < config.template > config.yaml && exec nginx -g "daemon off;"`.
При этом `execenv` имеет очень небольшой размер — менее 1 МБ.


## Возможности

- Подстановка `${VAR}` из переменных окружения.
- Обработка одного или нескольких файлов за один запуск.
- Перезапись файлов на месте или рендер из input-файла в отдельный output-файл.
- Настраиваемое поведение при отсутствии переменной окружения.
- Запись через временный файл с заменой целевого файла только после успешного рендера.
- Опциональный переход в финальный процесс приложения через `exec(2)`.
- Опциональное удаление переменных из окружения запускаемой команды.
- Основной сценарий использования — Linux/Unix контейнеры.

## Ограничения

> [!IMPORTANT]
> - Размер буфера чтения по умолчанию — 256 KiB.
> - Максимальная длина имени переменной в плейсхолдере — 4 KiB. Более длинные незавершённые плейсхолдеры сохраняются как обычный текст.
> - Output-файл наследует права доступа от input-файла.
> - Максимальное количество отфильтрованных переменных окружения - 10000
> - Все параметры `execenv` нужно указывать перед `--exec`
> - Поддерживаются только Unix-like системы.

## Установка

### Сборка из исходного кода:

```sh
cargo build --release
```

Оптимизированный бинарник будет доступен по пути:

```sh
target/release/execenv
```

Проект требует **Rust 1.91** или новее.

### Скачать стабильный релиз

Скомпилированый бинарный файл последнего стабильного релиза доступен по адресу https://github.com/dsk13-stack/execenv/releases.

## Использование

```sh
execenv --files <file> [<file> ...] [--missing-env <mode>] [--exec <command> [args...]]
```

Также доступны короткие флаги:

```sh
execenv -f <file> [-m <mode>] [-e <command> [args...]]
```

### Аргументы файлов

Обычный путь к файлу - рендерится in-place:

```sh
execenv --files /app/config.yaml
```

Mapping рендерит один файл в другой:

```sh
execenv --files /templates/config.yaml=/app/config.yaml
```

Можно обработать несколько файлов за один запуск:

```sh
execenv --files /app/config.yaml /app/worker.yaml
```

или несколько mapping-аргументов:

```sh
execenv --files \
  /templates/app.yaml=/app/config.yaml \
  /templates/worker.yaml=/app/worker.yaml
```

## Отсутствующие переменные

`--missing-env` управляет тем, что произойдёт, если файл содержит ссылку на переменную окружения, которая не задана.

Доступные режимы:

| Режим | Поведение |
| --- | --- |
| `empty` | Заменить плейсхолдер на пустую строку. Используется по умолчанию. |
| `keep` | Оставить исходный плейсхолдер `${VAR}` без изменений. |
| `error` | Немедленно завершиться с ошибкой и не запускать команду. |

Пример:

```sh
execenv --files /app/config.yaml --missing-env error
```

Для production-окружений обычно безопаснее использовать `--missing-env error`, чтобы приложение не стартовало с неполной конфигурацией.

## Запуск команды

Если передан `--exec`, `execenv` сначала рендерит все указанные файлы. Если рендер успешен, утилита заменяет свой процесс указанной командой через `exec(2)`.

```sh
execenv \
  --files /templates/nginx.conf=/etc/nginx/nginx.conf \
  --missing-env error \
  --exec nginx -g "daemon off;"
```

Всё, что идёт после `--exec`, считается командой и её аргументами, включая значения, которые начинаются с `-`.

Если рендер завершился ошибкой, команда не запускается.

## Пример

Файл-шаблон:

```yaml
server:
  host: ${APP_HOST}
  port: ${APP_PORT}
```

Запуск:

```sh
APP_HOST=0.0.0.0 APP_PORT=8080 \
execenv --files /templates/config.yaml=/app/config.yaml
```

Итоговый файл:

```yaml
server:
  host: 0.0.0.0
  port: 8080
```


## Окружение запускаемой команды

По умолчанию команда наследует всё окружение `execenv`. Если переменные нужны только для рендера конфигурации, их можно удалить из окружения команды, запускаемой через `--exec`:

- `--unset-rendered-envs` (`-u`): удалить переменные, на которые ссылаются плейсхолдеры во всех обрабатываемых шаблонах.
- `--excluded-envs VAR1,VAR2` (`-x VAR1,VAR2`): удалить явно указанные переменные, даже если они не встречаются в шаблонах.
- Оба флага вместе: удалить объединение этих наборов переменных.

Переменные остаются доступны во время рендера. Удаление применяется только к окружению запускаемой команды

Например, если хотите удалить переменные найденные в шаблоне и дополнительно исключить `BOOTSTRAP_TOKEN`:

```sh
execenv \
  --files /templates/app.yaml=/app/config.yaml \
  --unset-rendered-envs \
  --excluded-envs BOOTSTRAP_TOKEN \
  --exec /app/server
```

Используйте `--unset-rendered-envs`, когда запускаемой команде больше не нужны переменные из шаблона конфигурации. 
Если шаблон содержит `${HOME}` или `${PATH}`, они тоже будут удалены из окружения команды. 
Для точного выбора переменных используйте `--excluded-envs`.

Суммарное количество уникальных удаляемых переменных из `--excluded-envs` и всех шаблонов не должно превышать 10 000. 
Повторы учитываются один раз. 
Превышение лимита завершает обработку с ошибкой и предотвращает запуск команды независимо 
от значений по умолчанию в плейсхолдерах и режима `--missing-env`.

## Пример Dockerfile

```dockerfile
FROM chainguard/nginx:latest

COPY target/release/execenv /usr/bin/execenv
COPY templates/nginx.conf /templates/nginx.conf

ENTRYPOINT ["/usr/bin/execenv"]
CMD ["--files", "/templates/nginx.conf=/etc/nginx/nginx.conf", "--missing-env", "error", "--exec", "/usr/sbin/nginx", "-c", "/etc/nginx/nginx.conf", "-e", "/dev/stderr", "-g", "daemon off;"]
```

## Синтаксис плейсхолдеров

`execenv` использует синтаксис placeholder'ов в стиле Spring Boot.

Поддерживаются две формы:

```text
${VAR}
${VAR:default}
```

Примеры:

```text
${DATABASE_URL}
${APP_PORT:8080}
${LOG_LEVEL:info}
${API_URL:https://localhost:8080/api}
```

Поведение:

| Плейсхолдер | Переменная | Результат |
|---|---|---|
| `${VAR}` | unset | зависит от `--missing-env` |
| `${VAR}` | `""` | пустая строка |
| `${VAR:}` | unset | пустая строка |
| `${VAR:default}` | unset | `default` |
| `${VAR:default}` | `""` | пустая строка |
| `${VAR:default}` | задана | значение переменной |

Если указано значение по умолчанию после `:`, флаг `--missing-env` для этого плейсхолдера не применяется.

Не поддерживаются:

```text
$VAR
${VAR:-default}
${VAR-default}
${OUTER.${INNER}}
```

## Замечания по безопасности

`execenv` не вычисляет shell-выражения и не исполняет значения переменных окружения как код. Команда после `--exec` запускается напрямую как программа с аргументами, а не через `sh -c`.

Удаление переменных из окружения команды уменьшает дальнейшее распространение секретов через окружение приложения и запускаемых им программ. При этом значения, подставленные в конфигурацию, остаются в сгенерированном файле.
Будьте осторожны с записью итоговых конфигураций в shared volumes, persistent storage, логи, support bundles или директории, доступные другим процессам.


## Поддерживаемые платформы

`execenv` предназначен для Unix-like систем, потому что `--exec` использует `exec(2)`. Основная целевая среда — Linux-контейнеры.
